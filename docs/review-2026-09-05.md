# 工程审查与修复（2026-09-05）

基线提交：`c5e6bae`。检查范围包括 Node HTTP/存储/队列、前端异步编辑、音频分析工作器与主要页面。以下是已修复的问题，并不代表对所有模型和平台做了完整安全审计。

## 已修复

- **媒体访问边界**：媒体路径原来允许下载 `manifest.json`、`project.json` 等非音视频文件，且仅校验文本路径。现在只接受媒体格式并检查真实路径，阻止符号链接/目录联接越界；应用级 Host 校验阻止 DNS 重绑定，写请求必须来自相同 Origin（命令行无 Origin 请求仍支持）。保留现有错误码兼容性。
- **播放兼容性**：`Range: bytes=-N` 原来被当成从头读取，现支持后缀/开放范围并正确拒绝无效范围；补齐 AAC、MP4、MOV 等媒体 MIME。
- **任务列表与落盘**：最新 100 条任务的限制原来会挤掉旧的活动任务，影响状态显示与恢复。现在保留全部活动任务和最近 100 条终态记录，持久化按序写入；拆分任务仅携带结果索引，不随轮询重复发送完整音频片段台词。
- **自动保存顺序**：同一句慢请求与后续修改可能同时提交。现在同一句按序保存，旧响应不覆盖新输入，失败草稿会与重试合并；生成/导出前等待台词保存。项目快照回写保留待保存的编辑，音色批量绑定回包也不会清掉另一个项目的草稿。
- **分人参数与保留内容**：预计人数原来只用于可选重叠检测，并未传给主要分人模型；现在使用本机 FunASR 支持的 `preset_spk_num`。克隆素材排除的重叠 ASR 整句原来未进入 Session，现保留台词和音频、默认不用于克隆；保留识别置信度，缺失值不伪装成 0%。这些分析修正适用于新任务，不重写已有录音结果。
- **长音频页面**：一次性渲染数百段会让其他对话人难以找到。现在每人每页 30 段，增加全 Session 搜索、对话人筛选、粘性复核工具栏、跨页原子保存、未保存提示与刷新保护；重新分配的片段按时间排序。
- **制作台与协作室**：章节标题下误用了全书生成数量，现改为本章统计；修复窄侧栏中角色选项与三个滑块撑破容器、需要横向滚动的问题。

## 验证方式

- `npm run verify`：语法检查通过，84 项 Node 回归测试通过，覆盖媒体 Range/访问边界、任务保留与保存顺序、跨 Session 隔离、批量校对原子性、分页与搜索。
- 在 `novel-voice` 环境的 `worker` 目录运行 `python -m unittest discover -s tests -v`：21 项通过，包括真实 FFmpeg 裁剪及模拟模型分析/音色设计。
- 浏览器对真实历史页面做只读检查，对人工编辑使用隔离测试数据，不改动用户录音、作品或音色绑定。
- 真实 531 段历史音频首屏由全部片段降为 39 个编辑节点（3 位对话人各自分页）；隔离会话验证了跨页保存、相同时间的稳定顺序、切换后草稿与页码恢复。
- 浏览器检查项目首页、制作台、协作室、音色库、模型中心与拆分页；协作室右侧列表宽度与滚动宽度均为 311px，不再横向溢出；本轮验收标签页未记录控制台错误。
